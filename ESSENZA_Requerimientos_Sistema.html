1. Introducción

ESSENZA es una plataforma de comercio electrónico especializada en la venta de fragancias de lujo para hombres y mujeres, con una curaduría exclusiva de las maisons más prestigiosas de Europa. El presente documento detalla todos los requerimientos funcionales y no funcionales del sistema necesarios para transformar la página web estática actual en una aplicación web dinámica, escalable y de alto rendimiento, utilizando como stack tecnológico Next.js 16 con App Router en el frontend, Supabase como backend-as-a-service (BaaS) para base de datos, autenticación y almacenamiento, y Vercel como plataforma de despliegue y edge computing.

La arquitectura propuesta sigue el paradigma de desarrollo fullstack serverless, donde Next.js actúa como capa de presentación y lógica de servidor mediante Server Components y API Routes, Supabase proporciona toda la infraestructura de backend sin necesidad de gestionar servidores, y Vercel garantiza un despliegue continuo con CDN global y funciones edge para una experiencia de carga ultrarrápida en cualquier ubicación geográfica.

1.1 Objetivos del Sistema

  • Crear una plataforma e-commerce completa y funcional para la gestión y venta de perfumes de lujo europeos, con catálogo dinámico, carrito de compras, procesamiento de pagos y gestión de órdenes.
  • Implementar un sistema de autenticación seguro con múltiples proveedores (email, Google, Apple) mediante Supabase Auth, incluyendo roles de usuario (cliente, administrador) y gestión de sesiones.
  • Desarrollar un panel de administración para la gestión de productos, inventario, órdenes, clientes y contenido editorial del sitio.
  • Garantizar una experiencia de usuario premium con tiempos de carga inferiores a 2 segundos, navegación fluida y diseño responsivo para dispositivos móviles y de escritorio.
  • Establecer una infraestructura escalable que soporte picos de tráfico durante campañas estacionales (Navidad, San Valentín, Black Friday) sin degradación del rendimiento.

1.2 Alcance del Proyecto

El alcance del proyecto abarca la transformación completa de la landing page estática actual de ESSENZA en una plataforma e-commerce fully dynamic. Esto incluye la implementación de un catálogo de productos gestionable desde un panel de administración, un sistema de carrito de compras persistente, integración con pasarelas de pago europeas, gestión de usuarios con autenticación segura, sistema de búsqueda avanzada con filtros por notas olfativas, marca, precio y género, así como funcionalidades de marketing como listas de deseos, newsletters y descuentos por categoría.

2. Arquitectura del Sistema

La arquitectura de ESSENZA se basa en un modelo three-tier desacoplado que aprovecha las capacidades serverless de Next.js y Supabase. La capa de presentación se ejecuta en los edge servers de Vercel mediante Server Components y Client Components, la capa de lógica de negocio reside en las API Routes y Server Actions de Next.js, y la capa de datos la proporciona Supabase con PostgreSQL, Row Level Security y funciones RPC para operaciones complejas.

2.2 Flujo de Datos

El flujo de datos de la aplicación sigue un patrón request-response optimizado. Cuando un usuario accede a una página de producto, Next.js genera la página mediante Server Components que consultan directamente a Supabase a través del cliente de servidor (supabase-server). Los datos se renderizan en el servidor y se envían como HTML al cliente, proporcionando un First Contentful Paint ultrarrápido. Las interacciones del usuario (agregar al carrito, filtrar productos, realizar checkout) se manejan mediante Server Actions que actualizan la base de datos de forma atómica y retornan el estado actualizado al cliente mediante revalidación de caché incremental (ISR).

3.3 Funciones SQL y Triggers

Se requieren funciones SQL y triggers en PostgreSQL para automatizar procesos críticos del sistema que deben ejecutarse de forma atómica en la base de datos, garantizando consistencia de datos y eliminando la necesidad de lógica duplicada en la aplicación.

  • handle_new_user(): Trigger AFTER INSERT en auth.users que crea automáticamente el perfil en la tabla profiles con datos del proveedor OAuth o email.
  • update_rating_avg(): Trigger AFTER INSERT/UPDATE/DELETE en reviews que recalcula el promedio de calificación (rating_avg) y el conteo de reseñas (review_count) en la tabla products.
  • decrement_stock(): Función RPC que decrementa el stock de un producto de forma atómica al confirmar un pedido, verificando que exista stock suficiente antes de la operación.
  • generate_order_number(): Función que genera números de pedido secuenciales con formato ESS-YYYY-XXXX usando secuencias PostgreSQL.
  • update_updated_at(): Trigger BEFORE UPDATE en todas las tablas con columna updated_at que actualiza automáticamente la marca temporal.

4.2 Flujo de Autenticación

El flujo de autenticación sigue el patrón PKCE (Proof Key for Code Exchange) para clientes públicos, que es el estándar de seguridad recomendado por OAuth 2.0. Cuando un usuario inicia sesión, Supabase genera un JWT firmado que se almacena en una cookie HTTP-only segura. Este token se envía automáticamente en cada petición al servidor, donde se verifica la firma y se extrae la información del usuario para aplicar las políticas RLS correspondientes. El token tiene una vigencia de 1 hora y se refresca automáticamente mediante un refresh token rotativo.

6. Requerimientos de Integración de Pagos

La integración con Stripe se realizará mediante Stripe Checkout, que proporciona una página de pago alojada y optimizada para conversión, cumpliendo con los estándares PCI DSS sin necesidad de manejar datos sensibles de tarjetas en el servidor. Además, se implementará Stripe Webhooks para recibir notificaciones asíncronas del estado de los pagos.

6.1 Flujo de Checkout

  • El usuario revisa su carrito y presiona 'Finalizar Compra'. El servidor crea una sesión de Stripe Checkout con las líneas de items, costos de envío, impuestos y descuentos aplicados.
  • Stripe redirige al usuario a la página de pago alojada, donde ingresa los datos de tarjeta y dirección de envío. La página soporta múltiples métodos de pago: tarjeta de crédito/débito, Apple Pay, Google Pay y SEPA Direct Debit para clientes europeos.
  • Al completar el pago, Stripe envía un webhook al endpoint /api/checkout/success que verifica la firma del evento y actualiza la orden en Supabase (estado: paid), decrementa el stock y envía confirmación por email al cliente.
  • Si el pago falla, Stripe envía un webhook de tipo checkout.session.expired y la orden se marca como cancelled automáticamente tras 24 horas.

9.2 Seguridad

La seguridad del sistema se fundamenta en múltiples capas de protección, desde la infraestructura hasta la aplicación. Supabase proporciona protección DDoS, rate limiting y encriptación en reposo y en tránsito por defecto. A nivel de aplicación, se implementan las siguientes medidas:

  • Row Level Security (RLS) en todas las tablas con políticas restrictivas por defecto (deny all), permitiendo solo las operaciones explícitamente definidas.
  • Validación de entrada con Zod en todos los Server Actions y API Routes, sanitizando datos antes de la inserción en la base de datos.
  • Protección CSRF mediante el patrón de cookies SameSite=Lax y verificación del header Origin en mutaciones.
  • Rate limiting en endpoints públicos con Vercel Edge Middleware (100 requests/minuto por IP) para prevenir abuso.
  • Headers de seguridad configurados en vercel.json: Content-Security-Policy, Strict-Transport-Security, X-Frame-Options DENY, X-Content-Type-Options nosniff.
  • Encriptación de datos sensibles (direcciones, datos de pago) en la base de datos usando pgcrypto de PostgreSQL.

9.3 Escalabilidad

La arquitectura serverless de Vercel y Supabase proporciona escalabilidad horizontal automática sin intervención manual. Se estiman los siguientes umbrales de capacidad para el primer año de operación:

  • Concurrentes: hasta 5,000 usuarios concurrentes en picos estacionales, con auto-scaling de Vercel Serverless Functions.
  • Catálogo: hasta 2,000 productos activos con búsqueda sub-200ms mediante índices GIN en PostgreSQL para búsqueda full-text.
  • Base de datos: Supabase Pro plan soporta hasta 8 GB de almacenamiento y conexiones concurrentes ilimitadas con connection pooling (PgBouncer).
  • CDN: Vercel distribuye assets estáticos desde 100+ edge locations globalmente, con cache hit ratio objetivo > 95%.

9.4 Disponibilidad y Monitoreo

  • SLA objetivo: 99.9% de uptime (Vercel Pro garantiza 99.99% para edge deployments)
  • Monitoreo: Sentry para error tracking, Vercel Analytics para Web Vitals, Supabase Dashboard para métricas de base de datos
  • Alertas: Configuración de alertas por email y Slack para errores críticos, caídas de servicio y picos de latencia
  • Backups: Supabase realiza backups automáticos diarios con retención de 7 días (Pro plan), con opción de Point-in-Time Recovery
  • Disaster Recovery: RPO < 1 hora, RTO < 4 horas con failover automático de Supabase
